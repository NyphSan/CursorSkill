# Token 监督与按难易选模（≥1.1.3）

主控在**每一次**接需求、派工前，必须做两件事：**(1) Token / 上下文压力自检**；**(2) 按任务难易与问题类型选模**。

## 0) 主控默认高配（老板口径：「max」）

| 角色 | 模型策略 |
|------|----------|
| **主控（主会话）** | **默认用当前账号可选的最高配 / 最强推理档**（UI 模型选择器固定；俗称「max」） |
| **子代理** | **不默认跟满配堆叠**；按轻/中/重分配（见下表）；中/重用 `inherit` 时才继承主控高配 |

### 「Max」易混点（Cursor 产品）

| 说法 | 实际含义 |
|------|----------|
| 老板说「主控用 max」 | → **主会话选高配模型**（Opus / GPT 高档 / Grok 高档等，以选择器里可用者为准） |
| 产品 **Max Mode** | 旧版**按请求**套餐的大上下文开关；现行**用量制**套餐多数已**去掉**单独 Max Mode，改在模型行里选 Context/Effort |
| 模型名带 Max（如某 Codex Max） | 只是模型商品名，≠ 必须开 Max Mode |

主控**不能**在代码里把主会话模型改成「Max」；须老板/操作者在聊天顶部**模型选择器**固定高配。子代理 `inherit` = 跟该选择。

## 1) Token / 上下文监督（每轮）

主控**没有**精确实时 token 仪表 API；以**可操作代理指标**监督，并在派工块或结案摘要中写明。

### 每轮自检清单

| 检查 | 红线 / 动作 |
|------|-------------|
| 主会话是否在堆大段源码/日志 | 禁止整文件粘贴；改读文件 + 摘要落盘 |
| 是否反复全文读 transcript / 大文档 | 只读 BOARD + 最新 records；摘要优先 |
| 子代理 prompt 是否过胖 | 只给必读路径 + 定界要点；禁止粘贴整份 ARCH |
| 并行子代理数量 | 同文件禁止双执行；并行 ≤ 合理（审核∥Gitea∥PM 可） |
| 对话是否过长该续温 | 以 `records/` 为准开新会话，不靠记忆硬撑 |

### 派工时必写（可并入「子代理派工」块）

```text
## 资源与选模
- 上下文压力：低 | 中 | 高（一句理由）
- 任务档：轻 | 中 | 重
- 选用模型：<slug 或 inherit>（理由一句话）
```

### 压力为「高」时强制动作

1. 停止往主会话塞大 diff / 长日志  
2. 重活立刻 Task 出去；主控只调度  
3. 建议老板：新开聊天续温（读 BOARD）  
4. 能用快模的绝不默认高配

## 2) 按难易与问题类型选模

### 当前 Task 子代理允许的 model slug（硬名单）

仅下列（以 Cursor 当前 Task 工具为准；名单变更时更新本表）：

| slug | 用途定位 |
|------|----------|
| `inherit` | 与主会话同模；默认「中档」架构/审核 |
| `composer-2.5-fast` | 轻量：git 提交、改 README、短脚本、机械搬文件 |
| `cursor-grok-4.5-high-fast` | 需要较强推理但仍要控成本的快路径（探索/定界草稿） |

**禁止**：向 Task 传入名单外的模型名；不可用则留 `inherit` 并在派工块说明「名单无目标模」。

### 选模矩阵（主控默认）

| 任务档 | 典型岗位 / 问题 | 默认 model |
|--------|-----------------|------------|
| **轻** | Gitea commit/push、BOARD/COMMIT 补录、机械 rename、短文档对齐 | `composer-2.5-fast` |
| **中** | EXEC 按 ARCH 施工、task-review 对照 DoD、薄 ARCH、PM 自审 | `inherit` |
| **重** | 总定界 ARCH、跨模块依赖/倒灌分析、疑难编译根因、大范围迁移方案 | `inherit`（主会话用高配时）或老板指定；子代理勿无故叠高配 |

### 问题类型微调

| 问题类型 | 倾向 |
|----------|------|
| 纯 git / 文件 stage / push | 轻 → `composer-2.5-fast` |
| 按清单改代码 + 编译 | 中 → `inherit` |
| 架构定界 / 越界风险高 | 中偏重 → `inherit`；主控先写清定界 |
| 探索「代码在哪」 | 可用 explore 类子代理 + `composer-2.5-fast` 或 `cursor-grok-4.5-high-fast` |
| 老板点名某模 | 若在硬名单内则用；否则说明不可用并给替代 |

### 成本原则

1. **主控高配、子代理分流**：主会话留高配调度；轻活必须降档 slug，禁止「全家 inherit 叠满配」  
2. **能轻则轻**：机械活禁止主控亲自高配硬扛  
3. **一份定界一份施工**：ARCH 中/重 → `inherit`；EXEC 可同档或降一档  
4. **审核勿再升档**：审核 `inherit` 即可  
5. **主会话留守调度**：主控回复短；细节在子代理与 records  

### 模型不可用时（排查顺序）

主控/子代理报「模型不可用 / 灰色 / 被忽略」时，按序核对并在派工块写原因：

1. **本组织 Task 硬名单**：名单外 slug **禁止传入**（Agent 工具会拒）→ 改 `inherit` 或名单内替代  
2. **Settings → Models**：默认 Hidden 的模型未勾选开启  
3. **套餐 / 额度**：Hobby 池更小；额度尽 → Dashboard Usage / Spending  
4. **地区 / 厂商政策**：部分模型不出现在列表（非 Cursor 单方可控）  
5. **Team / Enterprise 封禁**：管理员 Models 策略  
6. **旧版 Max Mode 残留**：用量制已去开关时，偶发「Max disabled」类拦截 → 试 Auto 或清会话；legacy 套餐则开/关 Max Mode  
7. **子代理 fallback**：套餐不含 / 需 Max 未开 / 被封禁 → Cursor 会忽略配置并降级（常见降到 Composer）

## 4) 老板可见的用量

精确账单以 Cursor 账户用量页为准；主控负责**行为级控耗**（选模 + 上下文卫生），并在批末 retro 记「本批是否出现高压力对话 / 是否误用高配」。
