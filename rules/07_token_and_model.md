# Token 监督与按难易选模（≥1.1.2）

主控在**每一次**接需求、派工前，必须做两件事：**(1) Token / 上下文压力自检**；**(2) 按任务难易与问题类型选模**。

---

## 1) Token / 上下文监督（每轮）

主控**没有**精确实时 token 仪表 API；以**可操作代理指标**监督，并在派工块或结案摘要中写明。

### 每轮自检清单

| 检查 | 红线 / 动作 |
|------|-------------|
| 主会话是否在堆大段源码/日志 | 禁止整文件粘贴；改读文件 + 摘要落盘 |
| 是否反复全文读 transcript / 大文档 | 只读 BOARD + 最新 records；摘要优先 |
| 子代理 prompt 是否过胖 | 只给必读路径 + 定界要点；禁止粘贴整份 ARCH |
| 并行子代理数量 | 同文件禁止双执行；并行 ≤ 合理（审核∥Gitea∥PM 可） |
| 对话是否过长该续温 | 以 `records/` 为准开新会话，不靠记忆硬撑 |

### 派工时必写（可并入「子代理派工」块）

```text
## 资源与选模
- 上下文压力：低 | 中 | 高（一句理由）
- 任务档：轻 | 中 | 重
- 选用模型：<slug 或 inherit>（理由一句话）
```

### 压力为「高」时强制动作

1. 停止往主会话塞大 diff / 长日志  
2. 重活立刻 Task 出去；主控只调度  
3. 建议老板：新开聊天续温（读 BOARD）  
4. 能用快模的绝不默认高配  

---

## 2) 按难易与问题类型选模

### 当前 Task 子代理允许的 model slug（硬名单）

仅下列（以 Cursor 当前 Task 工具为准；名单变更时更新本表）：

| slug | 用途定位 |
|------|----------|
| `inherit` | 与主会话同模；默认「中档」架构/审核 |
| `composer-2.5-fast` | 轻量：git 提交、改 README、短脚本、机械搬文件 |
| `cursor-grok-4.5-high-fast` | 需要较强推理但仍要控成本的快路径（探索/定界草稿） |

**禁止**：向 Task 传入名单外的模型名；不可用则留 `inherit` 并在派工块说明「名单无目标模」。

### 选模矩阵（主控默认）

| 任务档 | 典型岗位 / 问题 | 默认 model |
|--------|-----------------|------------|
| **轻** | Gitea commit/push、BOARD/COMMIT 补录、机械 rename、短文档对齐 | `composer-2.5-fast` |
| **中** | EXEC 按 ARCH 施工、task-review 对照 DoD、薄 ARCH、PM 自审 | `inherit` |
| **重** | 总定界 ARCH、跨模块依赖/倒灌分析、疑难编译根因、大范围迁移方案 | `inherit`（主会话用高配时）或老板指定；子代理勿无故叠高配 |

### 问题类型微调

| 问题类型 | 倾向 |
|----------|------|
| 纯 git / 文件 stage / push | 轻 → `composer-2.5-fast` |
| 按清单改代码 + 编译 | 中 → `inherit` |
| 架构定界 / 越界风险高 | 中偏重 → `inherit`；主控先写清定界 |
| 探索「代码在哪」 | 可用 explore 类子代理 + `composer-2.5-fast` 或 `cursor-grok-4.5-high-fast` |
| 老板点名某模 | 若在硬名单内则用；否则说明不可用并给替代 |

### 成本原则

1. **能轻则轻**：机械活禁止默认 `inherit` 高配主会话拖着干  
2. **一份定界一份施工**：ARCH 用中/重；EXEC 可同模或降一档（若 ARCH 极清晰）  
3. **审核与执行勿无谓叠两套高配**：审核可 `inherit`，不必再升  
4. **主会话留守调度**：主控回复短；细节在子代理与 records

## 3) 与 rules/02 的关系

- 可见派工协议不变  
- 本规则要求在派工块中**追加「资源与选模」**  
- Task 调用时必须填与矩阵一致的 `model`（轻档不得省略为默示高配）  

---

## 4) 老板可见的用量

精确账单以 Cursor 账户用量页为准；主控负责**行为级控耗**（选模 + 上下文卫生），并在批末 retro 记「本批是否出现高压力对话 / 是否误用高配」。
