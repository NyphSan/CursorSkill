# 主机运行环境门禁（≥1.1.9）

## 威胁模型（写死）

Cursor 偏 **IDE 辅助 Agent**：一旦拿到 Shell / 写文件 / 系统配置权限，**会主动改你的运行环境**（代理、环境变量、git/HTTP 设置、worker、证书路径等），且常以「帮你修好网络/环境」为理由，**不经口头确认就落盘**。

这不是偶发 bug，而是产品形态：Agent 默认把「能改通」当成目标。

## 两类改动（必须分清）

| 类型 | 例子 | 默认 |
|------|------|------|
| **仓内工作区** | `ORG_ROOT` / 游戏工程内源码、规则、records | 按 ARCH / 派工范围可写 |
| **主机运行环境** | WinHTTP / 系统或用户环境变量 / 全局 git config / 防火墙 / 证书 / 代理端口占用 / worker 常驻服务 | **默认只诊断，不写入** |

## 强制纪律

1. **默认 dry-run**：涉及主机运行环境的脚本，先打印「将改什么 → 影响什么 → 如何回滚」，不自动 apply。  
2. **写入前问老板**：任何 apply / 写环境变量 / 改代理 / 提权 / 安装常驻服务前，必须先问「是否继续」。  
3. **禁止偷改**：不得在排障、预检、续温过程中「顺手」改主机环境；诊断报告落盘即可。  
4. **主控唯一持钥**：OS 提权仍仅主控（`rules/00`）；Cloud / 子代理 / 网络岗均不得自行提权改主机。  
5. **Cloud + My Machines 加倍警惕**：worker 落在本机时，Cloud Agent 的 Shell **等同本机权限**；未获确认不得改代理/环境。  
6. **结案留痕**：若老板确认写入，结案文件写明改了哪些键/服务、备份路径、回滚命令。

## 主控派工检查

派工块若任务可能碰主机环境，必须多写一行：

```text
主机环境：只读诊断 | 待老板确认写入 | 已确认写入（附备份路径）
```

未写默认为 **只读诊断**。

## 与网络岗关系

- 网络岗可跑用户级探测与预检（`rules/08`）。  
- 需要改 WinHTTP / 系统代理时：**升级主控**，先问老板，再 apply。  
- 手册：`docs/ops/NETWORK_OPS_HANDBOOK.md`
