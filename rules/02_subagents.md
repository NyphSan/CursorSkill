# 子代理派工与可见性

- 主控留守主会话  
- 主程 / 执行 / 审核 / Gitea（重活）默认 **Cursor Task 子代理**（真子进程），禁止只「换帽子」假装已派工  
- 交付物：`projects/<Project>/records/...`  
- 同一文件不并行双执行  

## 为什么你看不见（常见原因）

1. **主控在主会话直接干了**（角色扮演），没有调用 Task → UI 无子代理卡片  
2. **子代理已结束**：卡片一闪而过；需看聊天里的 agent 链接或 records  
3. **未开 Multitask / 侧栏未展开**：后台子代理在 Agents / 子代理面板，不在主回复正文里跑进度条  
4. **未先宣告**：回复里没写「正在拉起子代理」，难以察觉  

## 主控强制可见协议（≥1.1.1）

每次拉起 Task **之前**，主控必须在主会话写出：

```text
## 子代理派工
- 岗位：主程 | 执行 | 审核 | Gitea | …
- 任务：一句话
- 可见性：将调用 Task；请在侧栏/Agents 查看运行中的子代理
```

拉起后（或完成后）必须再写：

```text
- 子代理链接：[岗位名](agent-id)
- 状态：运行中 / 已完成
```

（使用 Cursor 要求的 `[label](id)` 链到子代理。）

### Task 参数约定

| 场景 | `run_in_background` |
|------|---------------------|
| 用户开了 Multitask / 希望边看边调度 | `true`（侧栏可见，主控可继续看板） |
| 用户明确要盯着这一刀跑完 | `false`（阻塞至完成，完成后仍贴链接） |

默认：**优先 `true`**，并立刻刷新 BOARD「子代理：是 · 岗位 · 链接」。  
禁止静默 `Task` 且回复里零提及。

### 自检（派工后）

- [ ] 回复含「子代理派工」块  
- [ ] 含 agent 链接或明确「已完成 + 记录路径」  
- [ ] BOARD 已更新子代理行  

## 老板侧怎么看

1. 打开 **Agents / 子代理 / Multitask** 相关侧栏（名称随 Cursor 版本）  
2. 看主控消息里的 **子代理派工** 与 markdown 链接  
3. 看 `records/*/…` 是否出现新文件（落盘证明跑过）
