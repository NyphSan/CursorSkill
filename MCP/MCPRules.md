# MCP 使用规则

本文件约束 **本仓 / OrgOps 会话** 里怎么用 MCP。不替代各 MCP 服务器自己的鉴权。

## 调用前

1. 先发现工具 schema（参数名、必填项），再调用；不要猜字段
2. 产品名对得上再查对应服务器（Figma / Gmail / cursor-cloud 等）
3. 服务器状态是 `needsAuth` / `error` / `loading` 时：不当作可用；鉴权失败不要用浏览器绕过

## 写与读

| 动作 | 态度 |
|------|------|
| 只读诊断（本 run 信息、只读检索） | 可做 |
| 会对外发送 / 修改远端（发邮件、改 Figma、删标签） | 须任务明确要求 |
| 把 MCP 返回的密钥、token、邮件正文写入 git | **禁止** |

## 本环境常见服务器（盘点口径，D3 再对账）

| 服务器 | 典型用途 | 注意 |
|--------|----------|------|
| cursor-cloud | 本 Cloud Agent 诊断、环境、事件 | 只描述本 run；不要拿来改别人的 agent |
| Figma | 设计文件读写、Code Connect | 写操作前必须先加载对应 Figma skill；禁止跳过 skill 直接 `use_figma` |
| Gmail | 草稿/检索/标签 | 默认当敏感数据；不把邮件正文提交进仓 |

## 禁止

- 用 MCP 结果绕过 OrgOps 写域（例如把组织章程当本仓文件写进去）
- 用未授权 MCP 冒充已验证事实
- 在 skill 正文里写死私人 MCP endpoint 或密钥
